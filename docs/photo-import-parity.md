# 写真の撮影情報と配置

確認日: 2026-11-01。提供画像の iOS 1.18 を基準にし、公開説明の追加確認と独立実装を記録します。

[公式の旅行記事](https://note.com/plainwalk/n/nf160cabe8248)は、外部カメラで撮った写真も撮影日時と場所をもとに道へ置くと説明しています。[公式サイト](https://plainwalk.app/)も写真の時刻と撮影場所を保持する機能を説明しています。全状態の UI、元の補間閾値、HEIC/JPEG の内部処理までは公開資料から確定できません。

以前の実装では、写真の取り込み後に追加時の現在地と時刻を使っていました。現在は元画像を縮小する前に撮影情報を読み、次の順で場所を決めます。

1. 写真に有効な GPS がある場合、その撮影場所を使います。
2. GPS がなく、時差を含む撮影時刻を確定できる場合、保存済み・記録中の軌跡でその時刻の位置を探します。
3. 特定できない場合、現在地や地図上の位置を利用者が明示して選びます。別の写真の場所を無断で再利用しません。

軌跡の補間は独自実装です。中断や順序の不正な時刻、120 秒を超す欠損、1 km を超す区間、高い速度、精度の悪い点、複数の軌跡で候補位置が一致しない場合は推測しません。これらの数値が本家の内部仕様と同じとはしません。

タイムゾーンのない EXIF の時計を UTC と見なしません。元の現地日時の文字列は残し、確定した撮影時刻がなければ追加日時で一覧に並べることを画面で示します。`t = 0`、緯度・経度の 0 も有効な値として扱います。

| 対象 | 読み取りと保存 |
|---|---|
| iOS | ImageIO で提供された画像の EXIF / GPS を解析。縮小・LUT 加工後も日時・カメラ情報を保持。GPS は写真ピンとして保存し、加工画像への埋め込みは行わない |
| Web | JPEG の EXIF を範囲検査付きで解析。撮影情報をピンの JSON に保持。Canvas の加工 JPEG 自体には EXIF を埋め込まない |

Web は JPEG 以外の撮影情報を未取得として扱います。iOS の写真選択時に OS が情報を省いた場合も、取得できた情報のみを使います。元の写真ライブラリの画像は変更しません。

保存開始時には写真・日時・位置・ひとことを固定します。読み込み中に写真を置き換えたり、保存の画像処理中に画面を閉じたりしても、古い写真で新しい下書きを上書きしません。JPEG のバイト順・不正な参照・時差・緯度経度 0・中断・曖昧な軌跡は単体テストで、写真選択・保存・キャンセル・実際の IndexedDB はブラウザの操作試験で確認します。iOS は ImageIO と CoreImage を使う DEBUG 自己テストを Simulator で実行します。最新の成否は README の CI リンクを参照してください。

答え合わせの「らくがき」は、その地図の表示地域で描画画面を直接開き、閉じると元の地図へ戻ります。元アプリと同じ演出・全状態の一致や、カメラ・実歩行の実機試験が完了したという記録ではありません。
