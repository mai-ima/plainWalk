# 実機での開発者機能

## 開く

- Web: プロフィール → 設定 → 開発者モード → 実機検証・診断ログ。
- iOS / Playgrounds: ネイティブのメニュー → 実機検証、または設定から診断を開きます。通常起動は SwiftUI です。

通常の Xcode 版、前面記録用の Playgrounds 版、ブラウザ版を分けて結果を残してください。

## 使える確認

- 権限、位置精度、最終測位からの時間、記録点数、OS と実行環境。
- 保存の往復テスト。専用キー / 一時フォルダに書いて読み、照合して削除します。実際の記録・設定は上書きしません。
- DEBUG のネイティブ診断では、隔離した位置ジャーナルの復旧と重複排除、保存失敗・再試行、GPX / TCX と共有ファイルの互換テスト。
- Web の描画間隔、タップ領域の枠、GPS 状態 HUD。requestAnimationFrame の値は端末全体の FPS を保証しません。
- 手動の実機チェックリスト。未確認・確認済み・不具合ありを自分で選び、自動で合格にはしません。
- 座標・軌跡・写真・場所名・メモを除いた JSON の明示的な共有。Web ログは最大 250 件、SwiftUI 画面のイベントは最大 100 件です。

診断を開くだけで新しく位置情報・カメラ・マイクの許可を要求しません。診断を自動送信しません。Web の開発者モードをオフにすると HUD・枠とログを消去します。

## ネイティブ UI と保存の確認

1. 署名してインストールし、通常起動が SwiftUI の 3 タブになることを確認します。Canvas の白地図、標準ナビゲーション・シート・共有シートを実際に操作します。
2. 白地図のドラッグ・拡大縮小・現在地、記録・一時停止・再開・長押し終了、配色・レイヤーを確認します。
3. 答え合わせの MapKit、場所検索、標準 / 航空写真 / 3D、目的地としおりへの追加を確認します。
4. 履歴・カレンダー・詳細・統計・再生を開き、保存した距離・時間・単位と照合します。SwiftUI の再生と Web の動画書き出しは別機能です。
5. 写真・短い動画・ひとことを保存し、再起動後の表示と削除を確認します。Vision の切り抜き結果を見てからステッカーを共有します。
6. らくがきを地図上に保存し、歩行後の更新と再起動後の保持を確認します。日本の既知の地点で、実 GeoJSON から得た区域バッジが表示されることも確認します。
7. ノートの文章・紙・書体とスライダーによる配置調整を保存し、PNG を共有します。Web で配置した写真・道・ステッカーや未知の項目が失われないことを確認します。キャンバスの直接ドラッグは未実装です。
8. GPX / TCX と JSON を Files から取り込み、GPX・バックアップを共有します。同じバックアップを再取り込みして重複が増えないこと、不正ファイルや容量不足時に元の記録が残ることを確認します。
9. 共有白地図の出力 JSON に選んだ線だけが含まれ、日時・写真・メモが含まれないことを確認します。招待リンクや共同同期の試験ではありません。

## 背景 GPS と権限の確認（Xcode 版）

1. 実機で位置情報を許可して歩き始めます。一時停止・再開時の点数と経過時間を診断と照合します。
2. 画面をロックして 15 分以上歩き、復帰後の軌跡・距離・点数・Live Activity を比較します。
3. 拒否・概算位置・権限取消、通信切断、低電力状態を試します。使えない機能が動作中に見えないことを確認します。
4. アプリ終了・再起動、OS による終了、記録の復旧・破棄・保存を確認します。復旧した記録が二重保存されないことも確認します。
5. HealthKit の許可・拒否、Apple Watch 起源の歩数、ルートのないワークアウトを確認します。未許可とデータなしを区別できない場合を記録します。
6. Live Activity の作成・更新・停止・復旧、Dynamic Island を確認します。通常のウィジェットとは区別します。
7. VoiceOver、文字サイズ、ダークモード、縦横画面、セーフエリア、写真・マイクの拒否を試します。

Playgrounds は前面 GPS だけを対象にします。HealthKit・Live Activity 拡張・ロック中の継続記録の試験には Xcode 版を使います。Mac や位置情報のない Simulator の結果を歩行検証に数えません。

CI のコンパイル・起動画像、Simulator の自己テスト、iPhone の実歩行結果は分けて残します。背景 GPS・HealthKit・電池消費・実端末の権限・配布署名は、現時点で未検証です。

スリープ防止は、Web では beta とスリープ防止の両設定を有効にした記録中に Screen Wake Lock を使います。SwiftUI 版はスリープ防止設定と記録状態に応じて UIApplication の idle timer を使います。停止・一時停止で解除されることを確認してください。
