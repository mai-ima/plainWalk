# Android 1.1.0 の開拓距離と再現の限界

2026-11-10。取得済みAndroid 1.1.0 / versionCode 4を静的に追加解析しました。XAPK・base APKのSHA-256は以前の取得記録と一致します。元アプリを実行した結果や、現行iOSの仕様とは区別します。[24メソッドの位置・ハッシュ、呼出経路、8つの独立計算例](references/android-grid-research-2026-11-10.json)を保存しました。命令列・逆コンパイルソース・元アプリの画像は実装や公開リポジトリへ転載していません。

## 静的に確認した計算

| 対象 | 確認できた内容 |
|---|---|
| 原点 | PersistedDataのoriginLat / originLonを保存・復元。初回に届いた位置から未設定の原点を設定する経路があり、精度判定後の採用点とは限らない |
| 投影 | x = (経度 − 原点経度) × 111320 × cos(原点緯度 × π / 180)、y = −(緯度 − 原点緯度) × 110540 |
| セル | floor(x / 12)、floor(y / 12)。負の座標も数学的なfloorで判定 |
| 区間の按分 | 投影区間長に対しN = max(1, ceil(長さ / 2))。各小区間の中点を判定し、別に渡された距離 × 新規サンプル数 / Nを加算 |
| 同一セル | 同じセルのサンプルが続く間は、そのセルに入った際の新規判定を呼出し間でも保持。同一セル内の往復でも加算される場合がある |
| 記録の境界 | オフライン集計は全記録でセルの訪問数を共有するが、記録ごとに直前セル・新規フラグ・今回触れた集合をリセット。1件の加算を保存済み距離以下へ制限 |
| 切断 | 隣接点のlegが違う組は集計しない。その分岐自体では直前セルのフラグをリセットしない |
| 距離の入力 | 楕円体の反復計算。半径6378137、扁平率0.0033528106647474805、許容差1e−12、上限100回、非収束時は半径6371008.8の球面計算。Vincenty系の構造と整合するが、全式の数値オラクルは再現していない |
| 位置採用の一経路 | 記録処理の対象メソッドでは精度0〜40m、移動4m未満を無視、300m超はlegを増やして接続距離を0にする。自動開始など全入力経路の条件と同じとは断定しない |

これは中点サンプルの按分で、現在の独立実装の「セル境界で分割し16方向の径を近似する計算」とは異なります。古いAndroidの数式を現在のiOSの正解として採用し、既存の記録値を変更することはしませんでした。

## 独立実装で再現した誤差と処理時間

[数値レビュー](references/grid-consistency-review-2026-11-10.json)では、現在のWeb計算で次を確認しました。Swiftは同じ方針であることをコードで照合していますが、今回の新しい数値例をApple SDK上で実行した結果とはしません。

- 同じ1kmを1件から複数記録へ分割すると、2件で約989.19m、10件で約938.69m、100件で約435.37mとなる例があります。
- 既存1kmに同じ道の過去1mを取り込むと、総開拓距離が約1000.00mから994.19mへ減る例を再現しました。入力は現在のバックアップ検証を通過します。
- 40km区間を往復する有効な1,000点の入力では、クラウドのNodeで同期計算に約5.15秒かかりました。通常の歩行やiPhoneの所要時間へ換算はしていません。計算の分割・キャンセルを導入する設計上の課題です。

正確に同じ終点から続く記録へ末尾セルを引き継ぐ試作は、単純な分割の誤差を改善しました。しかし、その間に別の記録を挿入すると接続関係が変わり、約1000.00mから998.81mへ減る[反例](references/grid-scalar-tail-counterexample-2026-11-10.json)が残りました。セルごとの最大値と直近1件の末尾だけでは、任意の過去データの取り込みと、切断区間を勝手につながない条件を両立できません。試作は採用せず、アプリのソース・配布IPA・記録データは変更していません。

## 完全一致の判定で不足するもの

提供画像は過去のiOS画面、追加解析は古いAndroid版です。現在の公式公開版1.19.0には設定構成などの変更がありますが、同じ端末・OS・版・データで全画面と操作を比較できる記録は取得できていません。取得した公式24秒映像もブランド映像で、全操作の映像ではありません。

署名済みの独立版をiPhone実機で動かす環境もなく、配布中の実機用IPAは未署名です。公開資料だけでは、現行iOSの全画面・操作・背景処理・計算・共有サーバーとの寸分違わない一致を判定できません。独立した改善案を加えることと、元の完全再現が成立したと認定することは別です。現在の完全一致の目標は、比較対象と実機環境が不足した状態として扱います。
