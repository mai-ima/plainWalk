# 継続するユーザー要件

このスレッドで確認できる指示を再整理。別スレッドや外部の非公開会話ログを参照できたとは主張しない。

1. PlainWalk の細部までの完全再現を目標に、公式サイト、関連画像、サイト、動画を調査する。
2. iOS と Web の双方を対象とし、iPhone の画面、セーフエリア、タッチ、保存・復旧、オフライン、画面遷移の使用感を整える。
3. 有料プラン・購入・広告をなくし、実装する旧有料機能を無料で統合する。
4. 便利な追加機能は設定から beta を有効にして使えるようにする。
5. 中断して未完成を完成扱いにせず、実装可能な差分を継続して埋める。
6. 低品質な代用品で満たしたことにしない。公式との見た目・挙動の差分と、実機未検証を明記する。
7. GitHub の保存先はユーザー確認済みの `mai-ima/plainWalk`。作業の区切りごとにコミットを追加し、他の変更を上書きしない。
8. Vercel でも配信できる構成にする。Vercel への接続・デプロイはこちらでは行わず、ユーザーが GitHub から手動で Import する。

## 品質確認

- 根拠のある値は一次資料から照合し、独自の仮値と区別する。
- Chromium と WebKit のモバイル画面で代表的な実操作を確認する。
- 地理データは出典を記載し、実際の点と境界の判定をテストする。
- 保存済みデータを失う変更を避け、旧形式のバックアップに対応する。
- iOS 用の Swift は Xcode のビルド・実機試験が済むまで動作確認済みとしない。

## 追加された整理・配布要件

ファイル構造と配置を整理し、編集する正本・生成物・テスト・確認画像を分ける。通常の iOS / Xcode 版を保持したまま、Swift Playgrounds 用 `.swiftpm` と単体 ZIP の生成を追加する。本家の画像は複数を追加確認し、出典・版・実画面との違いを記録する。GitHub への段階的なプッシュと Vercel の手動 Import 方針は維持する。

## APK 調査と Swift / 実機検証

公式サイトを再確認し、App Store 以外の公開画像も参照する。取得した APK はバイナリの構成・権限・依存関係を解析して根拠を記録する。iOS は iOS の提供実画面を基準に、SwiftUI の UI と端末機能で本家の再現を目指す。実機検証用の開発者機能を追加する。完全一致を未検証で断定せず、内部コードや素材の丸ごとのコピーは独立実装の方針に含めない。

通常の iOS 起動は WebView を使わず、SwiftUI・Canvas・MapKit・標準のタブ／シート／ファイル・写真の機能を利用する。サブエージェントで実装と監査を分担し、確認できた不具合を修正して再検証する。APK は記録・保存・分類の呼び出し関係も照合し、Android の区間番号や編集フラグを iOS の欠損点と混同しない。
