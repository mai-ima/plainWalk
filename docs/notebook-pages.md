# 日付ごとの複数ページ

2026-11-10 の追加作業です。公式説明で確認できた「同日に複数枚」「歩かなかった日にも作成」を対象にします。ページ選択の正確な位置・アニメーション・書体は公開画像で確認できていないため、独立した操作UIです。[今回の公開資料調査](public-research-2026-11-10.md)に根拠と限界を残しています。

## 保存形式

既存の `notes[YYYY-MM-DD]` は移動せず、最初のページとして扱います。選択用IDは `legacy:YYYY-MM-DD` です。追加ページは `notePages[id]` に `id`・`day` と内容を保存します。これまでの日付単位のバックアップをそのまま読み込み、未知のページ・素材・ライブラリのフィールドも残します。旧版アプリは追加ページを表示できません。

歩数 `steps` は日付のデータで、追加ページには複製しません。最初のページを削除する場合は既知のページ内容を除き、`pageDeleted: true` と日付のメタデータを残します。他のページや歩数まで削除しません。

## 編集と取り込み

ページ切り替え・追加・日付の変更に先立って下書きを保存します。保存できなければ移動せず、下書きを残します。削除は確認を経て行います。保存中に別操作で内容が変わったページを無条件に上書きせず、別のページとして残す操作を用意します。

バックアップの同日・同IDの内容が違うときは、両方を残します。内容を比較してから `import:日付:連番` の追加IDを採番するため、同じバックアップを繰り返し取り込んでも同一内容を増殖させません。比較ではID・日付・歩数・削除印を除き、既定値を補います。未知のフィールドも内容として比較するため、それらを含む差分を黙って捨てません。

Native はノートだけの変更時に、変更していない歩行軌跡と開拓距離の再構築を省きます。保存前の検証とファイルの原子的な書き込みは維持します。
