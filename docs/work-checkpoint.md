2026-11-01 の一時中断時に保存した記録と、2026-11-09 の再開後の進捗です。中断時の検証結果と最新差分の結果を区別します。

## 2026-11-09 再開

MapKitの実カメラは高度により傾斜を制限し、今回の条件では要求55°に対して約35°でした。独立したMapKit対照で許容角度を求め、完了通知後の安定した実状態と、中心・距離・拡大縮小時の角度保持を検証します。写真下部の0.137ptの測定端数は表示画素へ整列して判定し、全配置欄と固有ボタンのOCR確認を維持します。これらの最終CIは検証中です。

ユーザーの再開指示を受け、追加差分のCI結果を確認しました。`41313257831` はSwiftの旧MapKit距離API3か所で本体・Playgroundsのコンパイルに失敗していたため、`MKMapPoint.distance(to:)` に修正しました。Webの動画モード検証は、同じPlaywright 1.57のChromiumでも実動画の読み込みと11シナリオが通過し、限定した繰り返し・CPU負荷でも再現しませんでした。条件は緩めず、新CIで再確認します。

再実行では本体・Playgroundsのコンパイルが通過しましたが、動画プレビュー待機のCI失敗と、撮影開始前のSimulator端末一覧再取得timeoutが再発しました。動画は実WebMの再生・保存・再表示とMP4の実デコーダ判定に分け、読み込み待機に上限とエラーを追加。Simulatorは最初に温めたUUIDと端末名を後続へ引き継ぎ、起動中の再一覧取得を避けます。

実行検証では、既に同じ地図範囲にある場合にMapKitの完了通知が省かれ、空の平面地図の待機が終了しない問題も判明しました。現在の地図範囲と実カメラの一致を確認して同一要求を完了扱いにし、通知を止めた同一位置の回帰を追加しています。既存の3D・中心・倍率の検証条件と期限は維持します。

その後の実行検証で、3D切り替え時に傾斜変更後の距離を再読して倍率が変わる問題を検出。変更前の距離にズーム倍率を掛け、中心も維持するよう修正しました。また、アプリ未起動時の独立したterminate命令でtimeoutしたため、起動と前プロセスの終了を1つのsimctl launch命令に統合しました。実表示・OCR・新しい完了ファイルの条件は維持します。

Web は再開後に単体49件、Chromiumの9スイート（地図描画12シナリオ）、構文チェック、ビルドが通過しました。実WebMの復号・再生・保存・再表示を確認し、MP4は実際のデコーダ失敗と停止した読み込みを区別します。動画のメタデータとフレーム待機にはそれぞれ8秒の上限があります。撮影でも実MP4の再生時間の進行を確認してから停止しています。

Webは86状態・113枚を再撮影し、全画像を個別に確認しました。ファイル名・SHA-256・可視状態を別の更新後監査記録に保存し、新規P0/P1所見はありません。写真専用効果を動画で隠したため、旧114枚のうち動画撮影フォームの追加1区間が不要になりました。撮影元は `722e90a798ec9c4b9ced14195e62bccb37e23c92` です。

Nativeは再開後のビルドが通過しましたが、現在のSimulator実行ではMapKitの3D pitch検証が未通過です。地図の表示範囲・写真一覧撮影の追加修正は、最新CIの実行確認待ちです。Native86枚の再撮影・文字確認・目視と公開更新が完了するまで、以前の結果を追加差分の成功と扱いません。
